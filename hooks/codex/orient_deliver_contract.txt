Known-not-submitted callback contract (source candidate; unvalidated)

Only exit 75 may opt in to repeated in-daemon delivery of the SAME report.
It promises no accepting turn/start was attempted. The adapter consumes all
stdin first, checks existing unresolved dispatch before connecting, verifies
server CODEX_HOME and leading UA product/version, then proves either:
  * exact target absent from an exhausted, well-formed loaded list; or
  * exact thread/read identity has notLoaded or systemError status.
Pause is checked before connecting, before each readiness75, and before final
75 classification. No thread resume, new owner, settings change or queue.

Exit 78: operator pause or supported-version mismatch (terminal, no retry).
Exit 1: socket/RPC/identity/pagination/status errors, no direct input,
post-submit rejection/unknown acceptance, and all other failures.
Unknown dispatch blocks even a later readiness75, until manual reconciliation.
Native callback75 is typed only after full stdin was written and before its
deadline. Partial stdin, EPIPE, timeout, signal and all other exits are fatal.

Native retry is explicit --retry-known-not-submitted, default false. Backoff
5/20/60 seconds saturates, not a finite number of attempts. The same report
stays pending; no poll/refresh, new message selection or beat while awaiting it.
One daemon-only UTC preparation header is frozen with the report before first
attempt; it warns delivery may be delayed and does not date underlying facts.
Accepted is actual complete output Ok, not handled. Presented is authored
after acceptance. Receipt failure is fatal, never an automatic replay.

delivery::DeliveryNotice::{Retry(RetryNotice), Accepted} is the observer seam.
RetryNotice has per-report attempt:u64, fixed reason:&'static str, delay:Duration.
write_complete_report accepts FnMut(DeliveryNotice); apply_prepared_news accepts
FnMut(&mut FacultyStore, &SigningKey, DeliveryNotice). Synchronous observer
receives the already-owned store, must not re-enter Storage or affect delivery.
CC liveness integration is NOT included here. Every report path has a hook,
including health-only and habit-only. Retry precedes sleep; every Ok emits
Accepted, including A accepted, B retries, B accepted in the same session.

One absolute --run-for deadline caps attempts and backoff. Async sleep yields
to the existing SIGTERM/SIGINT selector. A running synchronous callback still
has its bounded subprocess timeout; unrelated synchronous store/upkeep work
is not made hard-interruptible. A clean stop with pending unsent news writes
no Presented. Service Restart=no is retained (no service files in candidate).

ADOPTION PREREQUISITE, NOT IMPLEMENTED HERE:
Existing orient-ready.py ExecStartPre maps absent/notLoaded to exit1 and can
block entry to the daemon. A reviewed readiness-gate successor must keep exact
identity/version/pause/unknown guards, allowing ONLY typed known-unsent readiness
to enter the persistent daemon. No generic readiness failure may be ignored.
Installed adapter, launcher, unit, owner thread and pause state are untouched.
